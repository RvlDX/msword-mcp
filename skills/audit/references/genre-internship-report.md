# Genre module: internship, KP, PKL, and work-placement report

Load only when the artifact is explicitly an internship, Kerja Praktik, PKL, or work-placement report. Current program/faculty/university guide takes precedence. Do not transfer these checks to theses, articles, or ordinary technical reports.

Check host, unit, role, period, and scope against available records. Work descriptions and process claims must be supported by evidence or labeled recollection. Use company information, screenshots, source code, and personal data only with authorization.

Logbooks, consultation records, assessment forms, completion letters, and signatures are checked only when required by the current guide and only to the extent files show them.

Topic must align with program and work actually performed. Curiosity-driven learning is not presented as assigned company activity. If activity was mostly orientation or self-directed learning, state it honestly.

Check structure against the guide. Do not require company history, organizational chart, diagrams, or a specific framework unless the guide or scope calls for it.

For IT reports, distinguish current and proposed systems. Select diagrams that fit the topic. Connect proposed features to evidenced problems. Claim implementation, testing, deployment, or acceptance only with artifacts/records. Use PIECES, SWOT, or another framework only when it fits the evidence; never fabricate findings to fill categories.
