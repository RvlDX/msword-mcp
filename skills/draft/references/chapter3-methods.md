# Chapter III Research Methods

Pick the path that fits the research, not the path the template happens to show. Never force a quantitative design, an experiment, a hypothesis, or field research onto work that does not need it. A conceptual article, a document study, a qualitative study, and a design project each need judgment on their own terms.

## Quantitative path

- Name the design with a reason, not only a name.
- State the population, the sampling technique, and the sample size, with the formula when the sampling is probabilistic.
- State the instrument and the origin of every item.
- Plan validity and reliability tests.
- Give each hypothesis exactly one analysis technique, and write the assumption tests in full.
- Plan ethics, permission, and anonymity.
- Every dataset number must come from a real calculation on the user dataset. Never compute a statistic from memory and never present a rounded guess as a result.

## Qualitative path

- Pick one design (case study, phenomenology, grounded theory, thematic analysis, or descriptive) with a reason.
- State the paradigm and the approach, not only the design name.
- Define informant inclusion and exclusion criteria, the purposive or snowball technique, and the stopping rule (saturation), not only "until saturated".
- Attach the interview guide and the consent sheet in the appendices.
- Write the analysis stages in order: transcription, open coding, categorization, thematic. Never only name "thematic analysis".
- Plan member checking or triangulation for validity.
- Mark quote sources clearly and never quote, code, or count anything that is not in the transcript.
- State the limits honestly: transferable, not generalizable.

## R and D and prototyping path

- Name the development model (for example Prototyping, ADDIE, or Borg and Gall) and justify the choice. The guide usually does not prescribe one model, so choose the model that fits the work.
- Describe the design: architecture or workflow, scope, users, inputs, processes, outputs, data stores, controls, and security.
- Report implementation results with test evidence: what was built, what was tested, and what the test showed.

## Data collection techniques

- Observation: direct observation of the real process at the site.
- Interview: questions put to the site side to dig out needs, problems, and expected features. Record the date, the role (not necessarily the person name), the method, and the key points. Never fabricate an interview transcript.
- Literature study: books, journals, and company documents that support the analysis.
- Questionnaire and experiment: state the instrument, the respondents, and the procedure.
